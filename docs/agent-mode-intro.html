Agent 模式 Beta

DesignFlow 新增的智能创作模式 — 像设计师同事一样和你聊需求，聊清楚再出图。

为什么需要 Agent 模式

Chat 模式的问题

用户需要自己写完整 prompt，带上 /Gpt image 2 或 /Nano Banana pro 指令。对不熟悉 prompt 工程的运营同事来说，门槛高、出图效果不稳定。

后续修改也只能靠用户自己组织语言，系统不会主动给建议。

Agent 模式的解法

用户用自然语言描述目标，Agent 会主动补全缺失的信息 （风格、构图、用途等），像设计师同事一样聊清楚再出图。

不够清楚时弹出选项让用户点选，不用打字。方案确认后一键生成。

5 种决策动作

动作触发条件用户看到什么
ASK 缺关键信息（如主体、用途） Agent 问一个问题 + 可点击的选项按钮
CONFIRM 信息足够，生成前确认 方案摘要 + 确认 / 换方向 按钮
GENERATE 方案确认，开始出图 进入生图流程，显示进度
REFINE 已有图，用户给反馈 保留主体一致性，按反馈调整后重新出图
EXPLORE 同阶段停留过长（≥3轮） Agent 主动提案，打破僵局

关键设计决策

1 动态信息评估，不做固定轮次追问

7 个维度加权评分（主体 30 / 风格 20 / 情绪 15 / 构图 10 / 色彩 10 / 光线 10 / 用途 5）。 用户描述充分 → 0 次追问直接生成；描述模糊 → 只问最关键的 1 个问题。 阈值 60 分即可生成，不会陷入无限追问。

2 选项式交互，能不打字就不打字

ASK 阶段提供结构化选项按钮（如"电商海报 / 社媒配图 / 白底产品图"）， 点击即发送，系统自动提取为结构化信息。CONFIRM 阶段提供快捷操作 （确认生成 / 换方向）。输入框始终可用，用户随时可以手动打字补充。

3 LLM 负责对话，Engine 负责决策

Muse（LLM Agent）只负责理解用户、创意协作、生成回复。它不直接触发生图， 只通过 [[ACTION_INTENT]] JSON 块表达意图。最终是否生成、问什么问题， 由 Decision Engine（规则引擎）决定。两者解耦，Engine 可以 override LLM 的判断。

4 生图场景模板，贴合实际业务

5 个内置场景（白底产品图 / 产品场景图 / 电商海报 / 社媒配图 / 时尚画册）， 根据用户意图自动匹配。每个场景有专属的摄影要素 prompt 和负向词， 确保出图风格符合实际业务需求，不会跑偏成艺术创作。

5 真流式输出 + VLM 真传图质检

LLM 回复使用 SSE 逐 token 流式输出，用户看到打字机效果，不等待。 生成完成后 VLM 真正「看到」图片做视觉质检，返回质量评分和匹配度。

Chat 模式 vs Agent 模式

Chat 模式Agent 模式
交互方式 用户输入 /指令 + prompt，手动控制生图参数 自然语言描述目标，Agent 引导补充信息，点击选项确认
适用场景 熟悉 prompt 的高级用户、模板合成、批量生产 不熟悉 prompt 的运营同事、从想法到成图的探索式创作
追问机制 无追问，用户需自行组织完整 prompt 动态评估信息完整度，最多 1-2 次追问，可选按钮快速回答
Prompt 构建 用户手写，固定质量词追加 自动匹配场景模板，注入专业摄影要素和风格词
迭代能力 手动修改 prompt 重新生成 自然语言反馈 → 自动构建 refine prompt → 保留主体一致性迭代
质量反馈 无 VLM 视觉质检，返回质量分和匹配度
默认状态 每次打开页面默认进入 Chat 模式，Agent 模式需手动切换
