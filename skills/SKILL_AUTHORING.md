# DesignFlow 技能（Skill）编写规范

给技能作者和帮忙写技能的 Agent 看：DesignFlow 能怎样使用一个技能、有哪些限制、怎样写才能在平台上真正生效。
本文按当前代码整理，相关上限以代码为准：`backend/agent_skill_loader.py`、`backend/user_skill_store.py`、`backend/agent2/tools.py`、`backend/skill_whitelist.py`。

---

## 1. 一句话理解

DesignFlow 的技能是**给 Agent 看的说明书**：一个带 `SKILL.md` 的文件夹，里面可以放参考文档和参考图片。
平台只会**读**技能：读文字、按路径取图当参考图。**不会运行脚本、不会写文件、不会联网下载、不会修改技能本身。**
经过审核、加入白名单的系统技能例外：可以运行声明过的只读脚本，并开启出图后自检返修，见第 9 节。

技能写得再复杂，最终都要落到平台提供的几个动作上：读技能文件、取技能里的图、看图、生图、改图、问用户一个问题、记住用户偏好。

---

## 2. 目录结构

```
my-skill/
├── SKILL.md              必需。开头是元数据，下面是正文
├── references/           可选。参考文档，*.md 会自动列给 Agent
│   ├── workflow.md
│   └── prompt-rules.md
└── assets/               可选。参考图片，目录名随意
    └── poses/0001.jpg
```

- 一个技能就是一个文件夹，文件夹里必须直接有 `SKILL.md`。
- `references/` 下所有 `.md`（含子目录）会自动出现在技能的参考文件清单里；其他文件也能读，但要在正文里写清路径。
- 图片可以放在任何子目录，用相对路径引用，例如 `assets/poses/0001.jpg`。

---

## 3. SKILL.md 开头的元数据

```markdown
---
name: kids-lookbook
title: 童装 Lookbook
summary: 按动作库出同一个孩子的多姿势套图
description: Use when the user wants a kidswear lookbook or several poses of the same child and outfit ...
tags:
  - 童装
  - 套图
references_with_image:
  - references/reference-image-analysis.md
---
```

| 字段 | 必需 | 说明 |
|---|---|---|
| `name` | 是 | 内部名。只能用英文字母、数字、`-`、`_`，字母或数字开头，最长 81 个字符。写中文也能用，但内部会换成哈希名，**建议写英文**。 |
| `description` | 是 | **决定 Agent 什么时候自动用这个技能。** Agent 的系统提示里只放每个技能 description 的**前 200 个字符**，触发条件（什么需求该用、什么不该用）必须写在最前面。 |
| `title` | 否 | 界面上显示的名字，不写就用 name。建议写中文。 |
| `summary` | 否 | 技能列表里的一句话副标题。 |
| `tags` | 否 | 标签列表。 |
| `references_with_image` | 否 | 只在「AI 生图」模式、用户上传了参考图时生效：列出要和 SKILL.md 一起交给规划模型的参考文件。见第 6 节。 |
| `type` | 否 | 目前只有 `instruction`（默认），不用填。 |

元数据格式限制（平台用的是简化版解析，不是完整 YAML）：

- 列表只支持「换行 + `- 项`」的写法，**不支持** `[a, b]` 这种行内写法（会被当成一串文字）。
- 多行文字可以用 `|` 或 `>`，后续行要缩进。
- 不支持嵌套对象。

## 4. 技能放在哪里、谁能看到

| 类型 | 放在哪 | 谁能用 | 怎么更新 |
|---|---|---|---|
| 系统技能 | 服务器上 `AGENT_SKILL_PATHS` 配置的目录（默认项目里的 `skills/`） | 所有用户 | 直接改目录里的文件，下次加载即生效，不用重启 |
| 个人技能 | 用户在界面里上传 | 只有上传者自己 | 重新上传同名技能会整体覆盖 |

- `AGENT_SKILL_PATHS` 可以写多个目录，Windows 用分号隔开，例如 `./skills;\\NAS服务器\共享名\skills`。共享盘要用完整网络路径，不要用映射盘符。
- 个人技能不能和系统技能同名；每个用户最多 20 个个人技能。
- 系统技能每次使用时都会重新读取文件，维护时请先在别处改好再整个替换，避免 Agent 读到写了一半的文件。

## 5. 上传个人技能的限制

| 项目 | 限制 |
|---|---|
| 上传格式 | `.zip` 压缩包，或单独一个 `SKILL.md` |
| 压缩包大小 | 100MB |
| 解压后总大小 | 200MB |
| 压缩包内条目数 | 500 个 |
| 保存的文件数 | 300 个 |
| 一次上传 | 只能包含一个技能（一个顶层 `SKILL.md`） |
| 会保存的文本 | `.md .txt .json .jsonl .yaml .yml .csv .py .sh .js`，统一转成 UTF-8（支持 UTF-8 / GBK 原文） |
| 会保存的图片 | `.jpg .jpeg .png .webp`，会校验确实是图片 |
| 其他文件 | 跳过不存（`.gif`、`.pdf`、`.zip`、`.bak`、`.psd` 等），上传后会提示 |
| 自动忽略 | `.DS_Store`、`Thumbs.db`、`desktop.ini`、`__MACOSX/`、`__pycache__/`、`._` 开头的文件 |
| 拒绝上传 | 符号链接、绝对路径、含 `..` 或盘符的路径 |

上传后的提示（不会阻止上传）：

- SKILL.md 加上 `references_with_image` 声明的文件超过 28000 字：超出部分不会被使用。
- SKILL.md 里出现脚本或命令：平台不会执行，由 Agent 按脚本内容自己完成。
- `references_with_image` 声明的文件不存在。

## 6. 技能在两种模式下怎么被使用

### 6.1 Agent 模式（主要场景）

1. Agent 的系统提示里列出所有可用技能（name、title、description 前 200 字）。
2. 用户点名技能，或需求落在某个技能的 description 范围内时，Agent 调 `load_skill` 加载。
3. 加载得到的是 **SKILL.md 全文**（加上一段平台执行说明），**最多 28000 个字符**，超出部分截掉。参考文件不会自动带上。
4. 之后 Agent 按正文指引，用 `read_skill_file` 读参考文件，用 `use_skill_image` 取技能里的图，再生图。

### 6.2 「AI 生图」模式（用户在输入框里选了技能）

1. 由一个规划模型一次性读完技能，直接产出一段最终生图 prompt，然后生图。
2. 交给规划模型的只有：**SKILL.md**；用户上传了参考图时，再加上 `references_with_image` 声明的文件。合计最多 28000 字。
3. 这个模式下**不会**读其他参考文件，**不会**使用技能目录里的图片，最多看用户上传的前 3 张参考图。
4. 所以：如果技能离不开参考文件或技能里的图片，它只适合在 Agent 模式下使用；想两种模式都可用，就把核心规则写进 SKILL.md 本身。

## 7. Agent 能用的工具（技能可以依赖的能力）

| 工具 | 能做什么 | 关键限制 |
|---|---|---|
| `load_skill` | 加载技能主文件 | 最多 28000 字 |
| `read_skill_file` | 读技能目录里的任意文本文件 | **每个文件只返回前 28000 个字符**；只能读技能目录内的文件 |
| `run_skill_script` | 运行白名单技能声明过的脚本（见第 9 节） | 只限白名单里的系统技能；每次最多 30 秒；输出最多 28000 字 |
| `use_skill_image` | 把技能里的图片登记成图片 ID，用作参考图或看图 | 每次最多 12 张；只支持 jpg / jpeg / png / webp；不会显示给用户 |
| `generate_image` | 文生图、参考图生图 | 每次最多 6 张；每张最多 9 张参考图；一次调用只有一个画幅 |
| `analyze_image` | 看图，返回主体、风格、文字等描述 | 一次一张 |
| `ask_user` | 问用户一个问题，给 2–4 个选项 | 只用于主体不明确或缺必需信息，不用来确认比例、风格 |
| `remember` | 记住用户的长期偏好或店铺、商品信息 | 每条不超过 200 字 |
| `find_product_images` | 按完整货号从公司素材库取商品图 | 只能按完整货号查，不能浏览或搜索；类型：白底图、透明图、一双鞋角度、阴影图、模特图 |
| `remove_background` / `fill_background` | 抠图 / 抠图后铺纯色底 | — |
| `upscale_image` | 高清放大 | — |
| `vectorize_image` | 转矢量 SVG | — |
| `split_layers` | 拆分图层、转 PSD | — |
| `outpaint_image` | 扩图 | 只在用户明确要扩图时用 |
| `outfit_change` | AI 换装：给人物换指定服装 | — |
| `special_compose` | 特殊品模板合成（平台原生功能） | — |

### 生图参数

| 参数 | 可选值 |
|---|---|
| 模型 | `gpt-image-2.6`（默认）、`gpt-image-2.5`、`gpt-image-2`、`nano-banana-pro`、`nano-banana-2.1`、`seedream-5-5` |
| 画幅 | `auto`、`1:1`、`3:4`、`4:3`、`4:5`、`5:4`、`9:16`、`16:9`、`2:3`、`3:2`，以及仅 Seedream 支持的 `2:1`、`1:2`、`21:9` |
| 清晰度 | `1K`（默认）、`2K`、`4K`、`1.5K`（仅 Seedream）；Seedream 不支持 4K |
| 模式 | gpt-image-2.6 / 2.5 有 `flare`（快速，默认）和 `sunburst`（优质） |

技能里不要写死某个外部生图工具、API 或模型 ID；平台会把技能里提到的生图方式全部换成 `generate_image`。技能可以**建议**画幅和清晰度。

## 8. 平台做不到的事（技能里写了也会被跳过或改写）

Agent 加载技能时，会附上一段平台执行说明，下面这些情况按平台规则处理（白名单技能放开的两项见第 9 节）：

| 技能要求 | 平台的处理 |
|---|---|
| 运行脚本、命令行 | 不运行。Agent 用 `read_skill_file` 读脚本，按脚本逻辑自己完成；读不到就告诉用户这里用不了 |
| 写文件、保存 prompt 记录、日志、结果表 | 跳过。平台会把每张图的 prompt 和参数记在卡片上，图片自动放进画布 |
| 修改技能文件、同步素材库、重建索引 | 做不了。提示用户在自己电脑上完成后重新上传 |
| 首次生图前确认生图方式、模型、分辨率 | 不确认，直接用平台模型和技能建议的比例生成；用户主动指定的偏好用 `remember` 记住 |
| 调用外部 API、联网下载 | 不支持 |
| 出图后自评打分、自动重新生成 | 不做。出完图交给用户，按用户反馈只替换 prompt 里对应的部分重新生成 |
| 先出定调图再批量出 | 支持：先出定调图，用户确认后再出其余 |
| 只要 prompt、不出图 | 支持：按技能要求的格式直接给出 prompt |

## 9. 白名单技能

依赖查询脚本、需要出图后逐张检查的复杂技能，可以由管理员加入白名单，尽可能按技能原样执行。

### 9.1 条件

- 必须是**系统技能**：放在服务器 `AGENT_SKILL_PATHS` 目录（含共享盘）里。用户上传的技能永远不执行脚本，同名也不行。
- 由管理员在项目根目录的 `skill_whitelist.json` 里登记，修改后立即生效，不用重启。
- 能写入技能目录（例如共享盘）的人，等同于能在服务器上运行这些脚本，维护名单只放可信的人。

```json
{
  "skills": {
    "kids-lookbook": {
      "scripts": [
        "scripts/query_action_packs.py",
        "scripts/query_assets.py",
        "scripts/build_prompt_context.py"
      ],
      "self_check": { "enabled": true, "max_repairs": 2 }
    }
  }
}
```

### 9.2 放开的能力

| 能力 | 说明 |
|---|---|
| 运行声明过的脚本 | Agent 用 `run_skill_script` 调用 `scripts` 里列出的脚本，参数逐个传入（不经过命令行，无法拼接其他命令）；需要文件输入的参数（例如要检查的最终提示词）由平台写成临时文件，参数里写 `{input_file}` |
| 出图后自检返修 | Agent 用 `analyze_image` 按技能的检查项逐张检查，有问题只改 prompt 里对应部分重新生成；每张最多返修 `max_repairs` 次（0–3），仍不合格就如实说明 |

### 9.3 脚本要求

- 只放**只读**的查询、检查脚本：不写文件、不联网、不改资料库。同步素材、重建索引这类维护脚本不要列进来，在本机维护后直接更新技能目录。
- 只依赖 Python 标准库或服务器已有的包。
- 用相对脚本自身的路径定位数据（例如 `Path(__file__).parent.parent / "references"`），不要依赖当前目录或本机绝对路径。
- 输出要精简：只输出匹配的结果，超过 28000 字会被截断，并提示 Agent 加筛选条件重查。
- 输出里的技能目录绝对路径会被自动换成相对路径（例如 `assets/xxx/0007.jpg`），Agent 可以直接拿去取图。
- 检查类脚本用退出码表示是否通过（0 通过，非 0 不通过），并把原因打印出来。
- 运行时不会往技能目录写 `__pycache__`；每次最多运行 30 秒。

## 10. 写作建议

1. **触发条件写在 description 最前面**：Agent 只看得到前 200 个字符。写清「什么需求用、什么需求不用」。
2. **SKILL.md 控制在 28000 字以内**，越靠前越重要：超出部分会被截掉。把审美规则、默认值、硬规则写在主文件；长的说明、示例拆到 `references/`。
3. **单个参考文件也控制在 28000 字以内**：Agent 读文件时每个文件只拿到前 28000 个字符，后面的内容等于不存在。
4. **大数据不要做成一个大文件**。例如动作库、素材索引：
   - 按分类拆成多个小文件（如 `references/poses/single-fullbody-boy.md`），在 SKILL.md 里写清「什么条件读哪个文件」；
   - 或者提供一个精简目录文件，每条只留编号、分类和一句话描述，详细内容按编号拆到小文件里。
   - 一个上千条的 JSON / JSONL 整体放进去，Agent 只能看到开头一小部分，后面的条目永远不会被选中。
5. **在正文里写出准确的相对路径**：例如「动作参考图在 `assets/action-packs/originals/<分类>/<编号>.jpg`」。Agent 是按路径取文件，不能浏览目录。
6. **参考图用 jpg / png / webp**，控制单张大小（长边 2000 像素以内足够）；要用到的图在正文或索引里能按编号找到路径。
7. **把脚本逻辑写成文字规则**：平台不执行脚本。查询、筛选、随机抽取这类逻辑，最好在 SKILL.md 或参考文件里写成 Agent 能照做的步骤，而不只是「运行 xxx.py」。
8. **不要依赖本机路径**：例如 `E:/xxx` 这类原始素材路径只能用于维护说明，Agent 读不到。
9. **不要在技能里存放密钥、账号、个人信息**。
10. **写清每张参考图的职责**：多张参考图一起用时（动作图、人物图、产品图），说明哪张只取动作和机位、哪张只取人物身份，平台会要求 Agent 按这个写进 prompt。

## 11. 自检清单

上传或发布前对照：

- [ ] 文件夹里直接有 `SKILL.md`，开头有 `name`（英文）和 `description`
- [ ] description 前 200 个字符写清了触发条件
- [ ] SKILL.md 不超过 28000 字；每个参考文件不超过 28000 字
- [ ] 没有依赖运行脚本、写文件、调用外部 API 才能完成的步骤（白名单技能可以依赖已登记的只读脚本）
- [ ] 正文里引用的文件路径都真实存在，大小写一致
- [ ] 图片都是 jpg / jpeg / png / webp
- [ ] 打包时没有带上 `.bak`、`.zip`、`__pycache__`、`.DS_Store`
- [ ] 个人技能：压缩包不超过 100MB，解压后不超过 200MB，文件不超过 300 个
- [ ] 需要在「AI 生图」模式下用：核心规则写在 SKILL.md 里，需要的参考文件写进 `references_with_image`
